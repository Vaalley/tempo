@startuml
title Séquence - Check-in par QR code (Tempo V1)
actor "Participant" as User
participant "Frontend" as Frontend
participant "API\n(routes et services)" as API
database "PostgreSQL" as DB

note over Frontend, API
  JWT dans un cookie HttpOnly.
  Les écritures exigent Origin autorisé et X-CSRF-Protection: 1.
  Refus CSRF : 403 ; session invalide : 401 ; entrées Zod invalides : 400.
end note

note over Frontend, API
  Le propriétaire ou un ADMIN génère le QR par POST /api/bookings/:id/qr.
  Le QR ouvre /check-in#bookingId=...&token=...
  Seul le hash SHA-256 est stocké dans booking_qr_tokens.
  Un nouveau QR remplace le jeton précédent.
end note
User -> Frontend : Ouvrir le lien du QR code
activate Frontend
Frontend -> Frontend : Restaurer la session et lire bookingId et token
note right of Frontend
  Sans session, redirection vers /login
  en conservant le lien pour le retour.
end note
Frontend -> API : POST /api/bookings/:id/check-in\n{ token }
activate API
API -> API : Contrôler CSRF, session, entrées Zod
break Requête refusée
  API --> Frontend : 401 session / 403 CSRF / 400 données
  Frontend --> User : Afficher l'erreur
end

API -> DB : Charger booking_participants par booking_id et user_id\navec la réservation liée
activate DB
DB --> API : Participant et réservation, ou absence
deactivate DB
break Participant introuvable
  API --> Frontend : 403 Vous ne participez pas à cette réservation
  Frontend --> User : Afficher le refus
end
API -> API : Vérifier invitation_status = ACCEPTED
break Invitation non acceptée
  API --> Frontend : 409 Invitation à accepter avant le check-in
  Frontend --> User : Afficher le refus
end
API -> API : Vérifier start_at <= maintenant < end_at
break Créneau non commencé ou terminé
  API --> Frontend : 409 Check-in non ouvert / réservation terminée
  Frontend --> User : Afficher le refus
end
API -> DB : Charger booking_qr_tokens par booking_id
activate DB
DB --> API : Hash du jeton et expires_at, ou absence
deactivate DB
API -> API : Comparer SHA-256(token) au hash stocké\net vérifier expires_at > maintenant
break Jeton absent, expiré ou incorrect
  API --> Frontend : 403 QR code invalide ou expiré
  Frontend --> User : Afficher le refus
end
API -> DB : UPDATE booking_participants SET checked_in_at = maintenant\nWHERE id = :participantId RETURNING *
activate DB
DB --> API : Participant avec checkedInAt
deactivate DB
API --> Frontend : 200 - Participant mis à jour
deactivate API
Frontend -> Frontend : Retirer le fragment du QR de l'URL
Frontend --> User : Afficher la confirmation et l'heure du check-in
deactivate Frontend
@enduml
