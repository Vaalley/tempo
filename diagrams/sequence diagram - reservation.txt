@startuml
title Séquence - Réservation d'un espace (Tempo V1)
actor "Collaborateur" as User
participant "Frontend" as Frontend
participant "API\n(routes et services)" as API
database "PostgreSQL" as DB

note over Frontend, API
  JWT dans un cookie HttpOnly.
  Les écritures exigent Origin autorisé et X-CSRF-Protection: 1.
  Refus CSRF : 403 ; session invalide : 401 ; entrées Zod invalides : 400.
end note

== Consultation des espaces ==
User -> Frontend : Consulter les espaces
activate Frontend
Frontend -> API : GET /api/workspaces
activate API
API -> API : Vérifier la session
break Session invalide
  API --> Frontend : 401 Authentification requise
  Frontend --> User : Afficher l'erreur
end
API -> DB : Charger workspaces, triés par nom
activate DB
DB --> API : Liste des espaces
deactivate DB
API --> Frontend : 200 - Espaces
deactivate API
Frontend --> User : Afficher les espaces
deactivate Frontend

== Création de la réservation ==
User -> Frontend : Choisir espace, dates et visibilité
activate Frontend
Frontend -> API : POST /api/bookings\n{ workspaceId, startAt, endAt, visibility }
activate API
API -> API : Contrôler CSRF, session, entrées Zod
break Requête refusée
  API --> Frontend : 401 session / 403 CSRF / 400 données
  Frontend --> User : Afficher l'erreur
end

API -> DB : Rechercher l'espace par id
activate DB
DB --> API : Espace ou absence
deactivate DB
break Espace introuvable
  API --> Frontend : 404 Workspace not found
  Frontend --> User : Afficher l'erreur
end
API -> DB : Rechercher un chevauchement\nstart_at < fin demandée ET end_at > début demandé
activate DB
DB --> API : Conflit ou absence
deactivate DB
break Chevauchement détecté
  API --> Frontend : 409 Créneau déjà réservé
  Frontend --> User : Afficher le conflit
end
group Transaction : réservation et propriétaire
  API -> DB : BEGIN puis INSERT INTO bookings\n{ user_id, workspace_id, start_at, end_at, visibility }
  activate DB
  DB --> API : Réservation créée ou erreur
  deactivate DB
  alt Conflit concurrent : exclusion GiST (23P01)
    API -> DB : ROLLBACK
    activate DB
    DB --> API : Transaction annulée
    deactivate DB
    API --> Frontend : 409 Créneau déjà réservé
    Frontend --> User : Afficher le conflit
  else Insertion réussie
    API -> DB : INSERT INTO booking_participants\n{ booking_id, user_id, role: OWNER, invitation_status: ACCEPTED }\npuis COMMIT
    activate DB
    DB --> API : Transaction validée
    deactivate DB
    API --> Frontend : 201 - Réservation
    Frontend --> User : Actualiser la liste et afficher la confirmation
  end
end
note over API, DB
  Toute erreur de transaction annule les deux écritures.
  Les erreurs serveur inattendues donnent 500.
  Les invitations sont ajoutées après la création.
end note
deactivate API
deactivate Frontend
@enduml
